# Stack Overflow Answer Predictor API

FastAPI service serving the trained classification (will this be answered?) and quantile regression (how long might it take?) models, with SHAP-based explanations for each prediction.

## Folder layout expected

```
stackoverflow-answer-predictor/     <- run all commands below from HERE, not from api/
  api/
    app/
    requirements.txt
    Dockerfile
    .env              <- local-only, gitignored (see "Run locally" below)
  models/
    classification_model.txt
    regression_model_lower.txt
    regression_model_median.txt
    regression_model_upper.txt
    model_metadata.json
    regression_metadata.json
    tag_rate_lookup.json
    platform_context.json
```

Note: the Docker build context is the **project root**, not `api/` - this is necessary so the Dockerfile can reach the shared `models/` folder, which lives outside `api/`. See the Docker section below.

## Run locally

```bash
cd api
python -m venv venv
venv\Scripts\activate.bat        # Windows
pip install -r requirements.txt
```

Create `api/.env` (not committed to git) pointing at your local models folder:
```
MODELS_DIR=C:\path\to\stackoverflow-answer-predictor\models
```

Then run:
```bash
uvicorn app.main:app --reload
```

Visit http://127.0.0.1:8000/docs for interactive API docs (auto-generated by FastAPI) - you can send a test request directly from the browser.

## Run with Docker

Build and run from the **project root** (not from inside `api/`), since the Dockerfile needs access to the shared `models/` folder as well as `api/`:

```bash
cd stackoverflow-answer-predictor
docker build -f api/Dockerfile -t so-answer-predictor .
docker run -p 8000:8000 -e MODELS_DIR=/srv/models so-answer-predictor
```

Then visit http://127.0.0.1:8000/docs the same way as the local run above.

Requires Docker Desktop with virtualization enabled (WSL2 backend on Windows). The image is based on `python:3.13-slim` to match the local development Python version, with `libgomp1` installed via apt for LightGBM's compiled runtime dependency.

## Deploying (e.g. Render)

- **Root Directory**: leave blank (build context must stay at the project root)
- **Dockerfile Path**: `api/Dockerfile`
- **Environment Variable**: `MODELS_DIR=/srv/models`

## Known limitations

- `platform_context.json` is a static snapshot from the training dataset's final 30 days, not a live rolling computation. In a fuller production system this file would be refreshed periodically (e.g. daily) from a live data source. Here it's a fixed value, documented as such.
- `has_code_block` detection uses simple heuristics (``` fences, `<code>` tags, indented blocks) since live input won't arrive as Stack Overflow's own HTML the way training data did.
- Regression prediction intervals were calibrated on historical data (81.4% actual coverage against an 80% target) - they are a genuine estimate of uncertainty, not a guarantee for any single new question.
- Training was performed on Kaggle's environment (numpy 1.26, pandas 2.2); the serving API runs newer major versions (numpy 2.5, pandas 3.0) and was verified to produce correct predictions in this configuration.
