# Stack Overflow Answer Predictor API

FastAPI service serving the trained classification (will this be answered?) and
quantile regression (how long might it take?) models, with SHAP-based
explanations for each prediction.

## Folder layout expected

```
stackoverflow-answer-predictor/
  api/            <- this folder
    app/
    requirements.txt
    Dockerfile
  models/ 
    classification_model.txt
    regression_model_lower.txt
    regression_model_median.txt
    regression_model_upper.txt
    model_metadata.json
    regression_metadata.json
    tag_rate_lookup.json
    platform_context.json
```

## Run locally

```bash
cd api
python -m venv venv
venv\Scripts\activate.bat        # Windows
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Visit http://127.0.0.1:8000/docs for interactive API docs (auto-generated by
FastAPI) - you can send a test request directly from the browser.

## Example request

```json
POST /predict
{
  "title": "How to filter a pandas dataframe by multiple conditions?",
  "body": "I have a dataframe and want to filter rows where column A > 5 and column B == 'x'. Here's what I tried:\n```python\ndf[df.A > 5 & df.B == 'x']\n```\nBut I get an error.",
  "tags": ["python", "pandas"],
  "asker": {
    "reputation": 45,
    "upvote_count": 3,
    "downvote_count": 0,
    "account_created": "2023-01-15T00:00:00Z"
  }
}
```

## Run with Docker

```bash
docker build -t so-answer-predictor .
docker run -p 8000:8000 so-answer-predictor
```

## Known limitations

- `platform_context.json` is a static snapshot from the training dataset's
  final 30 days, not a live rolling computation. In a fuller production
  system this file would be refreshed periodically (e.g. daily) from a live
  data source. Here it's a fixed value, documented as such.
- `has_code_block` detection uses simple heuristics (``` fences, `<code>`
  tags, indented blocks) since live input won't arrive as Stack Overflow's
  own HTML the way training data did.
- Regression prediction intervals were calibrated on historical data
  (81.4% actual coverage against an 80% target) - they are a genuine
  estimate of uncertainty, not a guarantee for any single new question.
